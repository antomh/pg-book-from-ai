Глава 2.1. SELECT: проекция, WHERE, NULL и трёхзначная логика

Уровень: J · узел карты тем: T04 · PostgreSQL 17.11

Почему запрос «покажи книги без оценки» ничего не находит

Разработчик пишет первый серьёзный запрос: у части книг в поле rating нет значения, и нужно вывести именно их. Естественная попытка:

SELECT title FROM books WHERE rating = NULL;

Что будет выведено и почему: ничего — всегда, при любых данных, (0 rows). Запрос синтаксически корректен и не вызывает ошибки, поэтому ловушка не обнаруживается сразу. Разбор, почему так устроен SQL и как писать проверки правильно, — содержание этой главы. Попутно разберём общий каркас запроса: что именно делает SELECT, как читается конвейер FROM → WHERE → список выборки, и почему это важно понимать до изучения JOIN и агрегатов.

Учебные данные модуля

Модули 2–5 работают с одной и той же предметной областью «читательский дневник». Полный набор данных на этот модуль:

CREATE TABLE authors (
    author_id  integer PRIMARY KEY,
    name       text    NOT NULL
);

CREATE TABLE books (
    book_id    integer PRIMARY KEY,
    title      text    NOT NULL,
    author_id  integer REFERENCES authors (author_id),
    year       integer,
    rating     integer
);

INSERT INTO authors VALUES
    (1, 'Александр Пушкин'),
    (2, 'Николай Гоголь'),
    (3, 'Лев Толстой');

INSERT INTO books VALUES
    (1, 'Евгений Онегин',   1, 1833, 5),
    (2, 'Руслан и Людмила', 1, 1820, 4),
    (3, 'Мёртвые души',     2, 1842, 4),
    (4, 'Война и мир',      3, 1869, 5),
    (5, 'Анна Каренина',    3, 1878, NULL),
    (6, 'Детектив XXI века', NULL, 2021, 3);

Синтаксис вставки строк — /docs/17/sql-insert.html; конструкторы значений VALUES — /docs/17/queries-values.html. Две строки здесь принципиальны для примеров NULL: у «Анны Карениной» нет оценки, у «Детектива» не указан автор.

Минимум теории: что такое запрос

«Процесс выборки данных из базы (или команда для такой выборки) называется запросом. В SQL для задания запросов используется команда SELECT» — так начинает раздел «Overview» документации (/docs/17/queries-overview.html, 7.1; перевод дословный). Общий вид команды там же:

[ WITH with_queries ] SELECT select_list FROM table_expression [ sort_specification ]

Выполнение запроса документация описывает как конвейер: «табличное выражение содержит предложение FROM, за которым необязательно следуют WHERE, GROUP BY и HAVING. Необязательные предложения WHERE, GROUP BY и HAVING задают конвейер последовательных преобразований таблицы, полученной в предложении FROM. Все эти преобразования порождают виртуальную таблицу, строки которой передаются в список выборки для вычисления выходных строк запроса» (раздел 7.2 Table Expressions, /docs/17/queries-table-expressions.html). Список выборки «определяет, какие столбцы промежуточной таблицы реально попадут в вывод» (7.3 Select Lists, /docs/17/queries-select-lists.html).

Запомним порядок: сначала фильтрация строк (WHERE), затем вычисление выражений списка выборки. На этом порядке построена глава 2.8: оконные функции нельзя вызывать в WHERE именно потому, что WHERE выполняется раньше них.

Список выборки: проекция

«Простейший вид списка выборки — *, выдающий все столбцы, которые порождает табличное выражение. В остальных случаях список выборки — это разделённый запятыми список выражений значений» (7.3.1, /docs/17/queries-select-lists.html; что считается выражением значения — раздел 4.2 Value Expressions, /docs/17/sql-expressions.html). Выражение — это не только столбец: арифметика, вызовы функций, константы. Метку столбца задаёт AS (7.3.2 там же):

SELECT title,
       2026 - year AS age_years,
       rating IS NULL AS unrated
FROM books;
      title       | age_years | unrated
------------------+-----------+---------
 Евгений Онегин   |       193 | f
 Руслан и Людмила |       206 | f
 Мёртвые души     |       184 | f
 Война и мир      |       157 | f
 Анна Каренина    |       148 | t
 Детектив XXI века|        5 | f
(6 rows)

Что выведено и почему: по строке на каждую книгу (фильтрации нет); каждому столбцу результата соответствует одно выражение списка; age_years вычислено из года издания; в последнем столбце — булев результат предиката IS NULL. Заметьте: NULL-поле «Детектива» (author_id) не участвует в выражениях, а NULL в rating «Анны Карениной» отражён как t в unrated — предикат IS NULL как раз и возвращает TRUE для отсутствующего значения.

Замечание: SELECT без FROM — расширение PostgreSQL

PostgreSQL разрешает опустить FROM и вычислять выражения напрямую: SELECT 2+2;. В разделе Compatibility справочной страницы SELECT это указано как расширение относительно стандарта («PostgreSQL allows one to omit the FROM clause...») — /docs/17/sql-select.html. В других СУБД для этого иногда требуется фиктивная таблица.

WHERE: фильтр строк

Формальное определение — раздел 7.2.2 «The WHERE Clause» (/docs/17/queries-table-expressions.html): «синтаксис: WHERE search_condition, где search_condition — любое выражение значения, возвращающее значение типа boolean. После обработки предложения FROM каждая строка полученной виртуальной таблицы проверяется на условие поиска. Если результат условия — истина, строка остаётся в выходной таблице, иначе (то есть если результат — ложь или NULL) она отбрасывается».

Курсив на «или NULL» — ключевая часть. Условие WHERE — не «двухпозиционный» фильтр: в SQL у логического выражения три возможных исхода, и в WHERE выживает только TRUE.

NULL и трёхзначная логика

NULL — это не ноль и не пустая строка, а маркер «значение отсутствует/неизвестно». Документация формулирует так: «не пишите expression = NULL, потому что NULL не "равен" NULL. (NULL представляет неизвестное значение, и неизвестно, равны ли два неизвестных значения.)» — раздел 9.2 Comparison Functions and Operators, /docs/17/functions-comparison.html. Отсюда и результат первого запроса главы: rating = NULL даёт не TRUE и не FALSE, а NULL — и строка отбрасывается. Все строки.

Как ведёт себя NULL в логических операторах — таблицы истинности раздела 9.1 Logical Operators (/docs/17/functions-logical.html; «SQL использует трёхзначную логику: true, false и null, где null означает "неизвестно"»):

aba AND ba OR b
TRUENULLNULLTRUE
FALSENULLFALSENULL
NULLNULLNULLNULL

и NOT NULL → NULL. Правило простое: NULL «заражает» выражение, если результат нельзя определить без неизвестного (FALSE AND NULL = FALSE — результат уже решён ложью первой части; TRUE OR NULL = TRUE — аналогично). Это стандартное поведение SQL, а не особенность PostgreSQL (Silberschatz, Database System Concepts, 7-е изд., глава 3, раздел «Null Values»).

Правильные проверки: IS NULL и IS DISTINCT FROM

Чтобы найти отсутствующее значение, есть специальный предикат: «expression IS NULL — проверить, что значение равно null» (раздел 9.2, /docs/17/functions-comparison.html). Он возвращает TRUE/FALSE, никогда NULL:

SELECT title FROM books WHERE rating IS NULL;
     title
---------------
 Анна Каренина
(1 row)

Обратная проверка — IS NOT NULL: «выражение IS NOT NULL — проверить, что значение не равно null» (там же). «Книги с известной оценкой»:

SELECT title FROM books WHERE rating IS NOT NULL;
      title
---------------
 Евгений Онегин
 Руслан и Людмила
 Мёртвые души
 Война и мир
 Детектив XXI века
(5 rows)

Что выведено и почему: пять книг из шести с известным рейтингом; «Анна Каренина» без рейтинга не прошла проверку — её и нашёл запрос выше.

Для сравнения «на неравенство, где NULL — обычное сравнимое значение» документация предлагает IS DISTINCT FROM: «не равно, где null трактуется как сравнимое значение. 1 IS DISTINCT FROM NULL → t (а не NULL). NULL IS DISTINCT FROM NULL → f» (там же). Это двухзначный оператор — выход всегда TRUE/FALSE.

Наконец, частый приём «либо равен X, либо NULL» — именно двухзначные предикаты, объединённые явно:

SELECT title FROM books
WHERE rating = 4 OR rating IS NULL;
      title
----------------
 Руслан и Людмила
 Мёртвые души
 Анна Каренина
(3 rows)

Что выведено и почему: три строки — две с рейтингом 4 и одна без рейтинга; уберите OR rating IS NULL — останутся две, потому что rating = 4 для NULL-строки даёт NULL, а не TRUE.

Проверь себя

Вопрос 1. Что вернёт SELECT count(*) FROM books WHERE rating = NULL; и почему?

Ответ. Ноль строк при любых данных: rating = NULL вычисляется в NULL (NULL не «равен» NULL), а WHERE пропускает строку только при TRUE — «ложь или NULL» отбрасываются (разделы 7.2.2 и 9.2 документации: queries-table-expressions.html, functions-comparison.html). Правильно — WHERE rating IS NULL.

Вопрос 2. Вычислите без запуска: чему равно rating > 3 AND NOT (author_id IS NULL) для книги «Анна Каренина» (rating = NULL, author_id = 3) и для «Детектива» (rating = 3, author_id = NULL)?

Ответ. «Анна Каренина»: NULL > 3 — NULL; NOT (3 IS NULL) — NOT FALSE = TRUE; NULL AND TRUE = NULL → строка отброшена. «Детектив»: 3 > 3 — FALSE; NOT (NULL IS NULL) — NOT TRUE = FALSE; FALSE AND FALSE = FALSE → отброшена. Обе строки не попадут в результат; таблицы истинности AND/OR/NOT с NULL — /docs/17/functions-logical.html.

Вопрос 3. Чем author_id IS DISTINCT FROM 1 отличается от author_id <> 1 на наших данных?

Ответ. «Детектив» (author_id = NULL): <> 1 даёт NULL → строка отбрасывается; IS DISTINCT FROM 1 даёт TRUE → строка остаётся, потому что «отсутствует» считается значением, отличным от 1. На остальных строках результаты совпадают. Семантика IS [NOT] DISTINCT FROM — /docs/17/functions-comparison.html.
