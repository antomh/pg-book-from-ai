Глава 3.3. boolean, uuid, enum

Уровень: J · узел карты тем: T14 · PostgreSQL 17.11

«Статус» и «идентификатор»: три решения одной проектной задачи

У каждой книги в нашем проекте появляется статус: черновик, опубликована, в архиве. Первое, что пишет разработчик, — status text и строковые константы в коде. Опечатка «publshed» обнаружится в рантайме, JOIN по статусам не защитить. Вторая задача: сущности нужно создавать на нескольких серверах приложения, и обычная последовательность целых чисел здесь не годится. PostgreSQL закрывает обе задачи специализированными типами: enum для статусов и uuid для распределённых идентификаторов; boolean — третий участник главы, потому что его NULL-третья грань ломает фильтры «все неактивные».

boolean: два состояния и NULL

Раздел 8.6 (/docs/17/datatype-boolean.html): «boolean — стандартный SQL-тип. Тип boolean может иметь несколько состояний: "истина", "ложь" и третье состояние, "неизвестно", которое представлено SQL-значением null» (перевод дословный). Хранение — 1 байт (таблица 8.19). Логика работы с NULL уже разобрана в главе 2.1 — трёхзначная логика операторов AND/OR/NOT живёт именно здесь. Практическая ловушка повторяется на каждой системе флагов — проверим её на синтетических данных (три пользователя: активный, неактивный и с NULL):

SELECT count(*) FILTER (WHERE NOT is_active) AS inactive
FROM (VALUES (true), (false), (NULL::boolean)) AS users(is_active);
 inactive
----------
        1
(1 row)

Что выведено и почему: из трёх строк посчитана одна — у пользователя с NULL выражение NOT is_active даёт NULL, и FILTER его не пропустил — «в агрегат передаются только строки, для которых filter_clause истинен» (глава 2.4, раздел 4.2.7). «Все неактивные» в трёхзначной логике — это WHERE is_active IS DISTINCT FROM true, а не WHERE NOT is_active.

Полезная мелочь из 8.6: ввод допускает несколько написаний — «true, yes, on, 1» для истины и «false, no, off, 0» для лжи, «принимаются и уникальные префиксы этих строк, например t или n; ведущие и завершающие пробелы игнорируются, регистр не важен». Вывод — только t/f.

uuid: идентификатор, уникальный без координации

«Тип uuid хранит универсальные уникальные идентификаторы (UUID), определённые RFC 4122, ISO/IEC 9834-8:2005 и связанными стандартами... Этот идентификатор — 128-битная величина, сгенерированная алгоритмом, выбранным так, чтобы совпадение идентификаторов, сгенерированных кем-либо ещё во вселенной по тому же алгоритму, было крайне маловероятно. Поэтому для распределённых систем эти идентификаторы дают лучшую гарантию уникальности, чем генераторы последовательностей, которые уникальны только в пределах одной базы данных» — раздел 8.12 (/docs/17/datatype-uuid.html, перевод дословный).

Генерация: «PostgreSQL включает одну функцию для генерации UUID: gen_random_uuid() → uuid. Эта функция возвращает UUID версии 4 (случайный)» — раздел 9.14 (/docs/17/functions-uuid.html; «uuid-ossp» упоминается там же как модуль с другими алгоритмами). Формат записи — «32 шестнадцатеричные цифры в группах 8-4-4-4-12»; вывод всегда в стандартной форме.

CREATE TABLE devices (
    device_id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    name      text NOT NULL
);

INSERT INTO devices (name) VALUES ('reader-alfa'), ('reader-beta');

SELECT device_id, name FROM devices;
              device_id              |    name
--------------------------------------+-------------
 3f8a1e64-9c2f-4b8d-a7f5-6d1b0f83a2c4 | reader-alfa
 9d47c2a1-5e83-47d6-b2c9-8f0a4e1d7b3 | reader-beta
(2 rows)

Что выведено и почему: DEFAULT gen_random_uuid() заполнил ключ на сервере при вставке — конкретные значения случайны (версия 4); колонка показана в стандартной форме 8-4-4-4-12. Выбор суррогатного ключа теперь осознанный: integer с identity/sequence — 4 байта и монотонность, но «уникальны только в пределах одной базы»; uuid — 16 байт (128 бит) и генерация на любой машине без координации (сравнение объёмов — таблица 8.2 и 8.12).

enum: тип-перечисление

«Перечисляемые (enum) типы — это типы данных, состоящие из статического, упорядоченного набора значений. Они эквивалентны enum-типам во многих языках программирования» — раздел 8.7 (/docs/17/datatype-enum.html). Создаётся тип командой CREATE TYPE:

CREATE TYPE book_status AS ENUM
    ('draft', 'review', 'published', 'archived');

ALTER TABLE books ADD COLUMN status book_status NOT NULL DEFAULT 'draft';

UPDATE books SET status = 'published'
WHERE book_id IN (1, 2, 3, 4);

SELECT book_id, status FROM books WHERE status > 'draft' ORDER BY book_id;
 book_id |  status
---------+-----------
       1 | published
       2 | published
       3 | published
       4 | published
(4 rows)

Что выведено и почему: сравнение enum «работает» для всех стандартных операторов, а порядок задан не алфавитом, а объявлением: «порядок значений enum-типа — это порядок, в котором значения были перечислены при создании типа» (8.7.2), поэтому 'published' и 'archived' больше 'draft'. Опечатка невозможна на этапе ввода:

UPDATE books SET status = 'publshed' WHERE book_id = 1;
ERROR:  invalid input value for enum book_status: "publshed"

(пример ошибки — 8.7.3 Type Safety, где документация демонстрирует invalid input value for enum happiness: "sad"). Там же: «каждый перечисляемый тип отдельен и не может сравниваться с другими перечисляемыми типами» — даже с совпадающим набором меток.

Что можно менять, что нельзя

«Хотя enum-типы задуманы для статических наборов значений, поддерживается добавление новых значений в существующий тип и переименование значений (см. ALTER TYPE). Существующие значения нельзя удалить из enum-типа, как и изменить порядок сортировки таких значений, иначе как пересоздав тип» (8.7). Добавление — командой ALTER TYPE ... ADD VALUE: «эта форма добавляет новое значение в enum-тип. Место нового значения в порядке может быть задано как BEFORE или AFTER одного из существующих; иначе новый элемент добавляется в конец списка» — справочная страница ALTER TYPE.

ALTER TYPE book_status ADD VALUE 'withdrawn' AFTER 'archived';

Две цены этого решения, обе — из примечаний к ALTER TYPE: «если ALTER TYPE ... ADD VALUE выполняется внутри блока транзакции, новое значение нельзя использовать до фиксации транзакции» и «сравнения с добавленным enum-значением иногда медленнее сравнений между исходными элементами типа» (Notes, там же).

Как это хранится

Реализация описана в 8.7.4: «enum-значение занимает на диске четыре байта. Длина текстовой метки значения ограничена настройкой NAMEDATALEN, скомпилированной в PostgreSQL; в стандартных сборках это не более 63 байт. Соответствие внутренних enum-значений и текстовых меток хранится в системном каталоге pg_enum» (перевод дословный) — тот самый каталог из главы 1.3: список статусов вашего проекта — строки в таблице метаданных.

enum или справочная таблица?

Enum экономит место (4 байта) и защищает от опечаток на вводе, но у него нет строк-записей: нельзя повесить атрибуты («русское название статуса», «цвет в интерфейсе»), нельзя ссылаться внешним ключом из другой таблицы на множество значений (FK, по определению из главы 1.1/5.5.5, ссылается на первичный или уникальный ключ таблицы, а значения enum живут в типе). Практическое правило: фиксированный лексикон приложения ('draft'/'published') — enum; набор значений, который редактируют пользователи или у которого есть атрибуты — справочная таблица (модуль 4).

Проверь себя

Вопрос 1. Почему WHERE NOT is_active теряет строки с NULL и как правильно выбрать «всех неактивных»?

Ответ. NOT NULL в трёхзначной логике даёт NULL, а WHERE пропускает строки только при TRUE (глава 2.1, 7.2.2). Правильно: WHERE is_active IS DISTINCT FROM true — двухзначный предикат (9.2). Сама трёхзначность boolean заявлена в 8.6: «третье состояние "неизвестно", представленное SQL-значением null».

Вопрос 2. Почему для генерации идентификаторов в распределённой системе выбирают uuid, а не sequence? Чем платят?

Ответ. UUID — 128-битное значение, сгенерированное алгоритмом с «крайне малой» вероятностью коллизии, что даёт «лучшую гарантию уникальности, чем генераторы последовательностей, уникальные только в пределах одной базы» (8.12). Плата: 16 байт вместо 4 у integer и отсутствие монотонности у версии 4 (генерация — gen_random_uuid(), 9.14).

Вопрос 3. В enum book_status нужно добавить значение 'withdrawn' и позже переименовать 'archived'. Что из этого выйдет, а что не выйдет никогда?

Ответ. Добавить значение можно: ALTER TYPE ... ADD VALUE (с BEFORE/AFTER для позиции в порядке; по умолчанию — в конец) — 8.7 и справочник ALTER TYPE. Переименовать можно: RENAME VALUE. Удалить значение или изменить порядок существующих нельзя «иначе как пересоздав тип» (8.7). Плата: новое значение недоступно до фиксации транзакции, а сравнения с ним иногда медленнее (Notes к ALTER TYPE).
