Глава 10.1. Функции на SQL

Уровень: J · узел карты тем: T46 · PostgreSQL 17.11

Один запрос — в пяти местах кода

Запрос «средний рейтинг книги» понадобился приложению читательского дневника пять раз: в списке книг, в карточке, в отчёте, в API и в скрипте рассылки. Копия запроса засела в пяти файлах, и когда в формуле появилась поправка «не считать отзывы без комментария», четыре копии обновили, а пятую забыли. Знакомая история из обычного программирования решается обычным способом — вынести код в функцию. Только функция эта живёт не в приложении, а в самой базе данных, рядом с данными. PostgreSQL даёт для этого несколько языков; начнём с самого простого — функций, тело которых написано на обычном SQL.

Первая функция

Сначала договоримся о терминах через документацию. Раздел 36.3 User-Defined Functions (/docs/17/xfunc.html): «PostgreSQL предоставляет четыре вида функций: функции на языке запросов (функции, написанные на SQL) (раздел 36.5), функции на процедурных языках (функции, написанные, например, на PL/pgSQL или PL/Tcl) (раздел 36.8), внутренние функции (раздел 36.9) и функции на языке C (раздел 36.10)». Эта глава — про первый вид, следующая — про второй. Раздел 36.5 Query Language (SQL) Functions (/docs/17/xfunc-sql.html, далее цитаты дословные) объясняет главное свойство таких функций: «SQL-функции выполняют произвольный список SQL- операторов, возвращая результат последнего запроса в списке. В простом (не множественном) случае возвращается первая строка результата последнего запроса». И про тело: «тело SQL-функции должно быть списком SQL-операторов, разделённых точками с запятой... Если функция не объявлена возвращающей void, последним оператором должен быть SELECT или INSERT, UPDATE, DELETE или MERGE с предложением RETURNING».

Функция «средний рейтинг книги» на наших таблицах из главы 2.3:

CREATE FUNCTION avg_book_rating(p_book_id int)
RETURNS numeric
LANGUAGE sql
AS $$
    SELECT round(avg(rating), 2)
    FROM reviews
    WHERE book_id = p_book_id;
$$;

Разбор: LANGUAGE sql называет язык, на котором написано тело функции (полный синтаксис CREATE FUNCTION — в /docs/17/sql-createfunction.html); тело обёрнуто в долларовые кавычки $$...$$ из главы 2.6 — обычный строковый литерал. Параметры можно адресовать по имени (p_book_id), как здесь, или позиционно: «в старом числовом подходе аргументы адресуются с помощью синтаксиса $n: $1 ссылается на первый входной аргумент, $2 — на второй, и так далее» (36.5.1). Вызов функции ничем не отличается от вызова встроенной:

SELECT title, avg_book_rating(book_id)
FROM books
WHERE book_id IN (13, 14);
      title       | avg_book_rating
-------------------+-----------------
 Пиковая дама      |
 Полтава           |
(2 rows)

Что выведено и почему: для каждой строки books сервер выполнил тело функции — агрегат avg по отзывам этой книги (глава 2.4). «Пиковая дама» и «Полтава» появились в главе 6.2 и отзывов не получили, поэтому оба вызова вернули NULL — «все агрегатные функции, кроме count, возвращают null, когда не выбрано ни одной строки» (9.21 /docs/17/functions-aggregate.html): пустые ячейки в выводе — это он, NULL, psql рисует его пустым местом (глава 2.1).

Функция, возвращающая таблицу

Скалярной функции мало, когда нужен список. Раздел 36.5.10 SQL Functions Returning TABLE: «другой вариант — RETURNS TABLE(столбцы). В этом случае возвращаются все строки результата последнего запроса». Топ-3 книги по рейтингу:

CREATE FUNCTION top_books(p_n int)
RETURNS TABLE (book_id_out int, title_out text, avg_rating numeric)
LANGUAGE sql
STABLE
AS $$
    SELECT b.book_id, b.title, round(avg(r.rating), 2)
    FROM books b
    JOIN reviews r USING (book_id)
    GROUP BY b.book_id, b.title
    ORDER BY avg(r.rating) DESC, b.book_id
    LIMIT p_n;
$$;

SELECT * FROM top_books(3);
 book_id_out |       title_out        | avg_rating
-------------+------------------------+------------
           3 | Мёртвые души           |       5.00
           4 | Война и мир            |       5.00
           1 | Евгений Онегин         |       4.67
(3 rows)

Что выведено и почему: функция вернула множество строк, и FROM top_books(3) сработала как источник таблицы — «все SQL-функции можно использовать в предложении FROM запроса» (36.5.8 SQL Functions as Table Sources). Выводные столбцы названы book_id_out/title_out специально: «имена столбцов RETURNS TABLE — это по сути выходные параметры», и их имена конфликтуют с именами колонок таблиц в запросе; «вы можете избежать двусмысленности, выбрав другой алиас для таблицы внутри команды SQL» (36.5.1). В ORDER BY стоит вторичный ключ b.book_id, чтобы порядок при равных рейтингах был предсказуем — правило из главы 2.2 (ORDER BY без уникального ключа не даёт гарантий порядка): «Мёртвые души» (одна пятёрка — отзыв 17 из главы 8.1) и «Война и мир» (две пятёрки — отзывы 5 и 15) набрали по 5.00, и младший book_id встал первым. А вот «Пиковая дама» и «Полтава» в топ не попали вовсе: JOIN reviews отбрасывает книги без отзывов — внутреннее соединение из главы 2.3.

Метки изменчивости: обещание оптимизатору

В top_books появилось слово STABLE. Это метка изменчивости — «категория изменчивости — это обещание оптимизатору о поведении функции» (36.7 Function Volatility Categories /docs/17/xfunc-volatility.html, далее дословно):

  • «Функция VOLATILE может делать что угодно, включая изменение базы данных. Она может возвращать разные результаты при последовательных вызовах с одинаковыми аргументами. Оптимизатор не делает никаких предположений о поведении таких функций. Запрос с изменчивой функцией будет перевычислять её в каждой строке, где нужно её значение»;
  • «Функция STABLE не может изменять базу данных и гарантированно возвращает одинаковые результаты для одинаковых аргументов для всех строк в пределах одного оператора. Эта категория позволяет оптимизатору оптимизировать несколько вызовов функции в один вызов... безопасно использовать выражение с такой функцией в условии индексного сканирования»;
  • «Функция IMMUTABLE не может изменять базу данных и гарантированно возвращает одинаковые результаты для одинаковых аргументов всегда. Эта категория позволяет оптимизатору вычислить функцию заранее, когда запрос вызывает её с константными аргументами».

«VOLATILE — значение по умолчанию, если команда CREATE FUNCTION не указывает категорию» (36.7). Какую метку выбрать для avg_book_rating? Функция читает таблицу reviews — её результат зависит от содержимого таблицы, которое меняется между операторами, поэтому IMMUTABLE (обещание «одинаковый результат навсегда») — ложь и опасна. Но в пределах одного оператора действует один снимок данных (глава 6.3), поэтому честная метка — STABLE, как и у top_books. Совет документации: «для лучших результатов оптимизации помечайте функции самой строгой категорией изменчивости, которая для них допустима. Любая функция с побочными эффектами должна быть помечена VOLATILE, чтобы её вызовы не могли быть оптимизированы» (36.7). Комментарий в коде каталога повторяет то же: PROVOLATILE_IMMUTABLE 'i' /* never changes for given input */, PROVOLATILE_STABLE 's' /* does not change within a scan */ (pg_proc.h, строки 164–165). Проверим, что метка реально хранится:

SELECT proname, provolatile, prokind
FROM pg_proc
WHERE proname IN ('avg_book_rating', 'top_books');

ALTER FUNCTION avg_book_rating(int) STABLE;
    proname     | provolatile | prokind
----------------+-------------+---------
 avg_book_rating | v           | f
 top_books       | s           | f
(2 rows)

ALTER FUNCTION

Что выведено и почему: обе функции попали в системный каталог pg_proc — схему pg_catalog вы видели в главе 4.5. Колонка provolatile хранит метку одной буквой, и до ALTER FUNCTION у avg_book_rating виден "v" — значение по умолчанию (36.7); после ALTER станет "s". prokind равен "f" — «function» (значения prokind определены в pg_proc.h, строки 149–154). Поля каталога — prolang («OID языка», строка 44), prosrc («исходный текст», строка 115) — определены в src/include/catalog/pg_proc.h: каталог CATALOG(pg_proc, 1255, ...) объявлен в строке 30 на коммите 083ac033419f690758508e08c1736089384bbee8.

Как это исполняется

Механизм создания: команда CREATE FUNCTION обрабатывается функцией CreateFunction в src/backend/commands/functioncmds.c (строка 1011), которая через ProcedureCreate из src/backend/catalog/pg_proc.c (строка 70) пишет строку в каталог pg_proc — тело функции хранится как текст, язык — как OID на pg_language. Исполнение SQL-функции — работа файла src/backend/executor/functions.c («Execution of SQL-language functions», строка 3). При первом вызове init_sql_fcache (строка 583) разбирает тело на операторы и строит записи исполнения: «у нас есть запись execution_state для каждого запроса в функции. Каждая запись содержит дерево плана для своего запроса» (комментарий, строки 51–58). Дальше вы уже знаете путь из главы 9.1: каждый оператор тела проходит разбор, планирование и исполнение, а результат последнего оператора возвращается как результат функции. Вызов диспетчеризует fmgr_sql (строка 1029) — «менеджер функций» PostgreSQL находит обработчик нужного языка. Для SQL-функции это означает: без накладных расходов на новый язык, но и без вычислений, которые нельзя выразить запросом, — для этого есть PL/pgSQL, следующая глава.

Связь с теорией

Функции и процедуры, хранящиеся в самой базе данных, — часть стандарта SQL и учебников: Silberschatz (7-е изд., гл. 5 Advanced SQL, § 5.2 Functions and Procedures, с. 198) — там же объяснено, зачем выносить логику на сервер: целостность и переиспользование. Метки изменчивости — расширение PostgreSQL этой идеи: формализация понятия «чистая функция» для оптимизатора запросов (в терминах языков программирования — отсутствие побочных эффектов); именно поэтому IMMUTABLE-функции разрешены в индексных выражениях — требование из главы 8.2. Книга Моргунова «Основы языка SQL» использует в примерах стандартные процедурные расширения SQL/PSM; пометка: язык SQL-функций в PostgreSQL соответствует стандарту, а PL/pgSQL — диалект PostgreSQL (сравнение — в главе 10.2).

Проверь себя

Вопрос 1. Чем тело SQL-функции отличается от PL/pgSQL-функции с точки зрения того, что можно написать? Что функция возвращает, если операторов несколько?

Ответ. Тело SQL-функции — «список SQL-операторов, разделённых точками с запятой», а «SQL-функции выполняют произвольный список SQL-операторов, возвращая результат последнего запроса в списке» (36.5). Ветвлений и циклов в чистом SQL-теле нет; если функция не void, «последним оператором должен быть SELECT или INSERT, UPDATE, DELETE или MERGE с предложением RETURNING» (36.5). Управляющие конструкции дают процедурные языки — PL/pgSQL (глава 10.2).

Вопрос 2. Почему функцию avg_book_rating, читающую таблицу reviews, нельзя пометить IMMUTABLE, но можно STABLE?

Ответ. IMMUTABLE — обещание «возвращать одинаковые результаты для одинаковых аргументов всегда» (36.7). Результат функции зависит от содержимого reviews, которое меняется (новые отзывы), — обещание ложно, и оптимизатор, доверившись, может «вычислить функцию заранее» и отдать устаревшее значение. STABLE — обещание «одинаковых результатов... для всех строк в пределах одного оператора» (36.7): в рамках одного оператора действует один снимок данных (глава 6.3), так что метка честна. Общее правило: «помечайте функции самой строгой категорией, которая для них допустима» (36.7).

Вопрос 3. Что хранит сервер после CREATE FUNCTION и где? Какая колонка каталога отвечает за метку изменчивости?

Ответ. Функция — строка системного каталога pg_proc: тело как текст в prosrc, язык как OID в prolang, метка изменчивости — provolatile ('i'/'s'/'v'), вид — prokind ('f' для функции) — поля определены в src/include/catalog/pg_proc.h (CATALOG pg_proc — строка 30, provolatile — строка 74, prosrc — строка 115). CREATE FUNCTION обрабатывает CreateFunction (functioncmds.c, L1011), запись каталога создаёт ProcedureCreate (pg_proc.c, L70). Исполняет SQL-функцию src/backend/executor/functions.c: при первом вызове init_sql_fcache строит «запись execution_state для каждого запроса в функции... содержащую дерево плана» (строки 51–58).
