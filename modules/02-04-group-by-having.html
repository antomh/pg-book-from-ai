Глава 2.4. Агрегация: GROUP BY и HAVING

Уровень: J · узел карты тем: T07 · PostgreSQL 17.11

«Сколько книг у каждого автора» ломает SELECT

Отчёт требует числа: книг по каждому автору, средний рейтинг по автору. Разработчик пишет:

SELECT title, count(*) FROM books;
ERROR:  column "books.title" must appear in the GROUP BY clause or be used in an aggregate function
LINE 1: SELECT title, count(*) FROM books;
       ^

Ошибка пугает, но она точна: запрос одновременно просит построчные данные (title) и сводные (count(*)), а серверу нужно понять, какое именно title показать рядом с единственным числом. Текст сообщения берётся прямо из исходного кода сервера — функция анализа группировки в файле src/backend/parser/parse_agg.c, строка 1494 на базовом коммите (вызов errmsg("column \"%s.%s\" must appear in the GROUP BY clause or be used in an aggregate function", ...)). Эта глава — о том, как такие запросы писать правильно: агрегатные функции, GROUP BY, HAVING и FILTER.

Агрегатные функции: свёртка множества строк в одно значение

«Агрегатные функции вычисляют единый результат из набора входных значений» — раздел 9.21 Aggregate Functions, /docs/17/functions-aggregate.html. Базовый набор и их точная семантика по NULL:

  • count(*) — «вычисляет число входных строк» (NULL не различает — считаются все строки);
  • count(expr) — «вычисляет число входных строк, в которых входное значение не NULL»;
  • sum(expr) — «вычисляет сумму не-NULL входных значений» (для integer результат — bigint);
  • avg(expr) — «вычисляет среднее арифметическое всех не-NULL входных значений» (для integer результат — numeric).

В теории это операция агрегирования реляционной алгебры — свёртка множества в скаляр (Silberschatz, Database System Concepts, 7-е изд., глава 2, раздел 2.6 «The Relational Algebra», агрегатные операции; по-русски — Моргунов, PostgreSQL. Основы языка SQL, глава 6.3). Простейший запрос без всякой группировки:

SELECT count(*) AS books_total,
       count(rating) AS rated,
       sum(rating) AS rating_sum
FROM books;
 books_total | rated | rating_sum
-------------+-------+------------
           6 |     5 |         21
(1 row)

Что выведено и почему: count(*) — все 6 строк; count(rating) — только строки с не-NULL рейтингом (у «Анны Карениной» NULL); sum(rating) сложил только не-NULL значения: 5+4+4+5+3 = 21. Документация фиксирует и такой случай: «если запрос содержит вызовы агрегатных функций, но не содержит GROUP BY, группировка всё равно происходит: результат — одна строка группы (или ни одной, если она затем устранена HAVING)» (раздел 7.2.3, /docs/17/queries-table-expressions.html).

GROUP BY: свёртка по группам

Механика по документации (раздел 7.2.3): «GROUP BY используется, чтобы сгруппировать строки таблицы с одинаковыми значениями во всех перечисленных столбцах... эффект — объединить каждое множество строк с общими значениями в одну строку группы, представляющую все строки группы. Это делается, чтобы устранить избыточность вывода и/или вычислить агрегаты по этим группам». Ключевое правило из того же раздела: «в общем случае, если таблица сгруппирована, столбцы, не перечисленные в GROUP BY, не могут использоваться, кроме как внутри агрегатных выражений». Справочник SELECT формулирует причину: при наличии GROUP BY «выражениям списка SELECT нельзя ссылаться на несгруппированные столбцы вне агрегатных функций» — иначе для такого столбца было бы «больше одного возможного значения» (/docs/17/sql-select.html, раздел GROUP BY Clause).

SELECT author_id, count(*) AS books_cnt
FROM books
GROUP BY author_id
ORDER BY author_id;
 author_id | books_cnt
-----------+-----------
         1 |         2
         2 |         1
         3 |         2
           |         1
(4 rows)

Что выведено и почему: шесть строк книг свёрнуты в четыре строки-группы по значениям author_id (Пушкин — 2 книги, Гоголь — 1, Толстой — 2) плюс отдельная группа строк без автора. Правильный ответ на запрос из начала главы:

SELECT a.name, count(*) AS books_cnt
FROM books b JOIN authors a ON a.author_id = b.author_id
GROUP BY a.author_id, a.name
ORDER BY books_cnt DESC;
      name       | books_cnt
-----------------+-----------
 Александр Пушкин |         2
 Лев Толстой     |         2
 Николай Гоголь  |         1
(3 rows)

Что выведено и почему: сначала JOIN попарно соединил книги с авторами (5 строк, INNER JOIN из главы 2.3), затем строки сгруппированы по автору, и в каждой группе посчитан count(*). Порядок действий конвейера: FROM → WHERE → GROUP BY → HAVING → список выборки (глава 2.1). В GROUP BY указан и author_id: группировать только по имени рискованно — два разных автора-однофамильца молча склеятся в одну группу; уникальный ключ (суррогат из главы 1.1) в GROUP BY избавляет от этого, а name добирается следом, потому что функционально зависит от ключа.

HAVING: фильтр групп

«Если таблица сгруппирована с помощью GROUP BY, но интересны только определённые группы, можно использовать HAVING — подобно WHERE — для устранения групп из результата... Выражения в HAVING могут ссылаться и на сгруппированные выражения, и на несгруппированные (в которых тогда обязателен агрегат)» (раздел 7.2.3, /docs/17/queries-table-expressions.html). Практическое различие с WHERE документация показывает на примере: «предложение WHERE отбирает строки по несгруппированному столбцу (условие истинно только для продаж за последние четыре недели), а HAVING ограничивает вывод группами с суммарными продажами свыше 5000» (там же). То есть WHERE фильтрует строки до группировки, HAVING — группы после.

SELECT author_id, avg(rating) AS avg_rating
FROM books
GROUP BY author_id
HAVING count(*) > 1
ORDER BY author_id;
 author_id |     avg_rating
-----------+--------------------
         1 | 4.5000000000000000
         3 | 5.0000000000000000
(2 rows)

Что выведено и почему: HAVING оставил только авторов с более чем одной книгой. avg(rating) для Пушкина — (5+4)/2 = 4.5; для Толстого — (5+NULL)/1: avg считает только не-NULL значения, поэтому «Анна Каренина» не участвует ни в сумме, ни в делителе — среднее 5. Заметьте: агрегат в HAVING (count(*)) не обязан совпадать с агрегатами в списке выборки — «агрегатные выражения не обязаны быть одинаковыми во всех частях запроса» (7.2.3).

FILTER: агрегат с собственным условием

Одному агрегату можно дать персональный фильтр: «если указан FILTER, то в агрегатную функцию передаются только те входные строки, для которых filter_clause истинен; остальные строки отбрасываются» (раздел 4.2.7 Aggregate Expressions, /docs/17/sql-expressions.html). Пример из документации там же, на нашей таблице:

SELECT count(*) AS total,
       count(*) FILTER (WHERE rating >= 5) AS five_stars
FROM books;
 total | five_stars
-------+------------
     6 |          2
(1 row)

Что выведено и почему: оба агрегата «видят» одни и те же 6 строк, но второй дополнительно пропускает их через условие — книг с оценкой 5 и выше у нас две. FILTER удобнее, чем повторный проход JOIN/CASE по тем же строкам. Там же, в 4.2.7, зафиксировано, где агрегаты вообще допустимы: «агрегатное выражение может появляться только в списке результата или предложении HAVING команды SELECT. Оно запрещено в других предложениях, например WHERE, потому что они логически вычисляются до формирования результатов агрегатов».

Проверь себя

Вопрос 1. Почему SELECT title, count(*) FROM books; вызывает ошибку, и тремя способами почините запрос.

Ответ. count(*) сворачивает все строки в одну, а для title в этой единственной строке нет единственного значения — «столбцы, не перечисленные в GROUP BY, не могут использоваться кроме как в агрегатах» (7.2.3). Варианты: (1) убрать title из списка выборки; (2) добавить GROUP BY title; (3) обернуть title в агрегат, например min(title). Текст ошибки и точка генерации — src/backend/parser/parse_agg.c#L1494 на базовом коммите.

Вопрос 2. Чем WHERE отличается от HAVING и почему WHERE count(*) > 1 не сработает?

Ответ. WHERE фильтрует строки до группировки, HAVING — группы после неё. Агрегатные выражения запрещены в WHERE, потому что WHERE логически вычисляется до формирования результатов агрегатов (раздел 4.2.7 /docs/17/sql-expressions.html); для фильтра по агрегату есть HAVING.

Вопрос 3. В таблице 6 книг, одна без рейтинга. Что вернут count(*), count(rating) и avg(rating) по всей таблице?

Ответ. count(*) = 6 (все строки); count(rating) = 5 (только не-NULL); avg(rating) = 21/5 = 4.2 — sum и avg работают с не-NULL значениями (описания count/sum/avg — 9.21 /docs/17/functions-aggregate.html).
