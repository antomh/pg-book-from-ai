Глава 2.5. Подзапросы

Уровень: J · узел карты тем: T08 · PostgreSQL 17.11

«Книги выше среднего» и «авторы без книг»: два запроса, которые не написать без подзапроса

«Выведи книги с рейтингом выше среднего» — порог заранее неизвестен: он сам вычисляется по таблице. «Выведи авторов, у которых нет ни одной книги» — требует сравнения каждого автора со всем множеством книг. Обе задачи решаются подзапросом: SELECT внутри другого оператора. У второй задачи есть знаменитая ловушка с NOT IN, на которой спотыкаются и опытные разработчики, — разберём её на наших данных (в books.author_id есть NULL у «Детектива», в authors есть Крылов без книг).

Скалярный подзапрос: значение из запроса

«Скалярный подзапрос — это обычный SELECT-запрос в скобках, который возвращает ровно одну строку с одним столбцом... Запрос выполняется, и единственное возвращённое значение используется во внешнем выражении значений. Использовать запрос, возвращающий больше одной строки или больше одного столбца, — ошибка. (Но если при конкретном выполнении подзапрос не возвращает строк, ошибки нет: скалярный результат считается NULL.)» — раздел 4.2.11 Scalar Subqueries, /docs/17/sql-expressions.html.

SELECT title, rating
FROM books
WHERE rating > (SELECT avg(rating) FROM books)
ORDER BY book_id;
     title      | rating
---------------+--------
 Евгений Онегин|      5
 Война и мир   |      5
(2 rows)

Что выведено и почему: средний рейтинг по не-NULL значениям равен 4.2 (глава 2.4); порог вычислен один раз и сравнён с каждой строкой; строго выше 4.2 — две книги. Подзапрос здесь некоррелированный: не зависит от строк внешнего запроса.

Табличный подзапрос в FROM

Подзапрос может стоять и в FROM — как источник строк: «подзапросы, задающие производную таблицу, заключаются в скобки. Им можно назначить псевдоним таблицы и, опционально, псевдонимы столбцов... Более интересные случаи, которые не сводятся к обычному соединению, возникают, когда подзапрос включает группировку или агрегацию» (раздел 7.2.1.3 Subqueries, /docs/17/queries-table-expressions.html). Пример: средний рейтинг автора — но только у плодовитых авторов со средним не ниже 4.5; двухшаговая задача, где первый шаг «свернуть», второй «отфильтровать»:

SELECT name, avg_rating, books_cnt
FROM (
    SELECT a.name, avg(b.rating) AS avg_rating,
           count(*) AS books_cnt
    FROM authors a JOIN books b ON b.author_id = a.author_id
    GROUP BY a.author_id, a.name
) AS author_stats
WHERE avg_rating >= 4.5
  AND books_cnt > 1
ORDER BY avg_rating DESC;
     name      |     avg_rating     | books_cnt
----------------+--------------------+-----------
 Лев Толстой  | 5.0000000000000000 |         2
 Александр Пушкин | 4.5000000000000000 |         2
(2 rows)

Что выведено и почему: внутренний SELECT сгруппировал книги по авторам (по правилам главы 2.4), внешний отфильтровал результат как обычную таблицу. Обратите внимание на обязательный по смыслу псевдоним author_stats — производная таблица в FROM обязана иметь имя. Оба фильтра второго шага сработали по-разному: Гоголь (одна книга, среднее 4) не прошёл ни avg_rating >= 4.5, ни books_cnt > 1; Крылов вообще без книг не попал во внутренний SELECT — INNER JOIN его отсеял. (Среднее Пушкина 4.5 — (5+4)/2; Толстого 5 — NULL «Анны Карениной» не участвует.)

IN и NOT IN: сравнение со множеством

«Левое выражение вычисляется и сравнивается с каждой строкой результата подзапроса. Результат IN — true, если найдена хоть одна равная строка подзапроса. Результат false, если равной строки нет (включая случай, когда подзапрос не возвращает строк)» — раздел 9.24.2, /docs/17/functions-subquery.html. Ловушка — в NULL, и документация описывает её дословно: «если левое выражение даёт NULL, или если нет равных правых значений и хотя бы одна строка справа даёт NULL, результат конструкции IN будет NULL, а не false» (там же). Для NOT IN — зеркально: «...результатом NOT IN будет NULL, а не true» (раздел 9.24.3 там же).

Смотрим на нашу задачу «авторы без книг»:

SELECT name
FROM authors
WHERE author_id NOT IN (SELECT author_id FROM books);
 name
------
(0 rows)

Что выведено и почему: ни одной строки, хотя Крылов без книг в базе есть. Подзапрос вернул значения {1, 1, 2, 3, 3, NULL} — среди них NULL («Детектив» без автора). Для Крылова (author_id = 4) нет равных значений, но есть NULL справа — и NOT IN даёт NULL, строка отбрасывается WHERE (глава 2.1). Так NULL одного-единственного «Детектива» обнуляет весь отчёт. Уберите NULL из подзапроса — и всё заработает: NOT IN (SELECT author_id FROM books WHERE author_id IS NOT NULL) вернёт Крылова.

EXISTS и NOT EXISTS: «есть ли строки»

«Аргумент EXISTS — произвольный оператор SELECT или подзапрос. Подзапрос вычисляется, чтобы определить, возвращает ли он строки. Если он возвращает хотя бы одну строку, результат EXISTS — true, если не возвращает — false. Подзапрос может ссылаться на переменные окружающего запроса, которые ведут себя как константы при любом отдельном вычислении подзапроса. Подзапрос обычно выполняется ровно настолько, насколько нужно, чтобы определить, есть ли хотя бы одна строка, а не до конца» — раздел 9.24.1, /docs/17/functions-subquery.html. Три выделенных факта — три свойства EXISTS: он возвращает булево значение без NULL-тонкостей; подзапрос внутри него может быть коррелированным — ссылаться на строки внешнего запроса, как в примере ниже (но может быть и независимым, как подзапрос во FROM); и ему не нужно полное вычисление подзапроса.

Надёжная версия задачи про авторов без книг:

SELECT a.name
FROM authors a
WHERE NOT EXISTS (
    SELECT 1 FROM books b WHERE b.author_id = a.author_id
);
    name
-------------
 Иван Крылов
(1 row)

Что выведено и почему: для каждого автора подзапрос ищет хотя бы одну его книгу (связь через b.author_id = a.author_id — корреляция); EXISTS у Крылова — false, NOT EXISTS — true. NULL в чужих строках на результат не влияет: сравнение b.author_id = a.author_id для NULL-строки даёт NULL, эта строка подзапроса просто не находится — но другие строки, если они есть, корректно дают true. Правило практической безопасности: если в подзапросе возможен NULL в сравниваемом столбце — используйте NOT EXISTS вместо NOT IN.

ANY/SOME и ALL: сравнение с каждой строкой

«Левое выражение вычисляется и сравнивается с каждой строкой результата подзапроса с помощью заданного оператора... Результат ANY — true, если получено хотя бы одно true... SOME — синоним ANY. IN эквивалентен = ANY» — раздел 9.24.4; «...Результат ALL — true, если все строки дают true (включая случай, когда подзапрос не возвращает строк). NOT IN эквивалентен <> ALL» — раздел 9.24.5 (оба — /docs/17/functions-subquery.html). Пример: книги с максимальным рейтингом без GROUP BY и MAX:

SELECT title, rating
FROM books
WHERE rating >= ALL (SELECT rating FROM books WHERE rating IS NOT NULL)
ORDER BY book_id;
     title      | rating
---------------+--------
 Евгений Онегин|      5
 Война и мир   |      5
(2 rows)

Что выведено и почему: условие «рейтинг больше или равен каждому не-NULL рейтингу таблицы» истинно только для максимального значения. NULL в подзапросе пришлось исключить явно: 5 >= NULL даёт NULL, и с NULL внутри множества ALL не пришёл бы к true ни для одной строки — трёхзначная логика из главы 2.1 работает и здесь.

Проверь себя

Вопрос 1. Почему author_id NOT IN (SELECT author_id FROM books) вернул 0 строк, хотя в базе есть автор без книг? Как починить двумя способами?

Ответ. В подзапросе есть NULL (книга без автора): «если нет равных правых значений и хотя бы одна строка справа даёт NULL, результат NOT IN — NULL, а не true», и WHERE отбрасывает такие строки (9.24.3 /docs/17/functions-subquery.html). Способы: исключить NULL из подзапроса (WHERE author_id IS NOT NULL) или переписать на NOT EXISTS (...) — он не чувствителен к NULL.

Вопрос 2. Чем коррелированный подзапрос отличается от некоррелированного в плане вычисления?

Ответ. Некоррелированный не зависит от строк внешнего запроса — его результат можно вычислить один раз (как средний рейтинг выше). Коррелированный ссылается на переменные окружающего запроса («ведут себя как константы при любом отдельном вычислении подзапроса» — 9.24.1) и вычисляется в контексте каждой внешней строки: как EXISTS для каждого автора в нашем примере.

Вопрос 3. Что вернёт SELECT 5 = ANY (SELECT rating FROM books) при рейтингах {5, 4, 4, 5, NULL, 3}? А 5 = ALL (...)?

Ответ. ANY: true — есть строки, где сравнение 5 = 5 истинно (для NULL-строки сравнение даёт NULL, но достаточно одного true). ALL: false — есть строки (например, rating = 4), где сравнение даёт false; ALL даёт NULL, когда среди сравнений нет ни одного false и есть хотя бы одно NULL (правила ANY/ALL — 9.24.4–9.24.5 /docs/17/functions-subquery.html).
