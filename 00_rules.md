# 00_rules.md — Общие правила проекта «Интерактивный учебник по PostgreSQL»

Этот файл — источник истины по версии PostgreSQL, базовому коммиту и форматам ссылок.
Все главы, примеры и материалы проекта обязаны следовать правилам, зафиксированным ниже.
Любой промпт в этом проекте ссылается на данный файл и не может ему противоречить.

## 1. Зафиксированная версия и базовый коммит

| Параметр | Значение |
|---|---|
| Мажорная ветка | PostgreSQL 17 |
| Минорный релиз | **17.11** (последний опубликованный стабильный на момент фиксации) |
| Тег релиза | `REL_17_11` |
| Базовый коммит (полный SHA-1) | `083ac033419f690758508e08c1736089384bbee8` |
| Коммит | «Stamp 17.11.» (автор Tom Lane, дата коммита 2026-08-10) |
| Версия документации | <https://www.postgresql.org/docs/17/> |

Этот SHA используется **во всех файлах учебника без исключений**. Ветка `master` и любые
другие коммиты для ссылок на исходный код не используются.

### 1.1. Обоснование выбора ветки 17

- Ветка 17 — актуальная мажорная ветка с длительной поддержкой (до ноября 2029 г.);
  правила проекта прямо называют 16.x / 17.x целевыми ветками.
- Ветка зрелая: за ней закреплено 11 минорных релизов, поведение стабилизировалось,
  документация устоялась.
- Ветка 18 новее, но правила проекта ориентируются на 16/17; кроме того, для аудитории
  «от нуля до junior+» ветка 17 — сегодняшний мейнстрим в продакшене и у хостинг-провайдеров.
- Опубликовано и сверяемо: сайт документации `/docs/17/` сейчас отрисовывает именно
  «PostgreSQL 17.11 Documentation», то есть версия документации **побайтово совпадает**
  с зафиксированным тегом `REL_17_11`. Это исключает расхождения между текстом учебника,
  документацией и исходным кодом.

### 1.2. Почему не 17.12 (примечание о выборе минорного релиза)

Тег `REL_17_12` (коммит «Stamp 17.12.» от 2026-11-09) уже существует в репозитории,
но на дату фиксации правил (2026-11-12) релиз **не опубликован**: страницы
`https://www.postgresql.org/docs/17/release-17-12.html` ещё нет (HTTP 404), сайт
документации отрисовывает 17.11. Выбран последний **полностью опубликованный** релиз.
После публикации 17.12 версия в этом файле **не** обновляется автоматически: смена
базового коммита — отдельное явное решение, требующее перепроверки всех ссылок учебника.

### 1.3. Журнал верификации (выполнено 2026-11-12)

- `https://www.postgresql.org/docs/17/` — HTTP 200, заголовок страницы:
  «PostgreSQL: Documentation: 17: PostgreSQL 17.11 Documentation».
- Тег `REL_17_11` через GitHub API (`/repos/postgres/postgres/commits/REL_17_11`)
  разрезолвлен в коммит `083ac033419f690758508e08c1736089384bbee8`.
- Страница релиза `https://www.postgresql.org/docs/17/release-17-11.html` — HTTP 200.
- Шаблон ссылки на исходный код проверен на реальных файлах (HTTP 200):
  `src/backend/access/heap/heapam.c`, `src/backend/access/transam/xact.c`.

## 2. Шаблоны ссылок

### 2.1. Документация PostgreSQL

Базовый префикс — только эта версия:

```
https://www.postgresql.org/docs/17/<путь-к-странице>
```

Примеры:

```text
https://www.postgresql.org/docs/17/tutorial.html
https://www.postgresql.org/docs/17/sql-select.html
https://www.postgresql.org/docs/17/runtime-config.html
```

Правила:

- Ссылки на `/docs/current/`, `/docs/18/`, `/docs/16/` и любые другие версии — **запрещены**.
- Если утверждение есть в документации — ссылка на документацию обязательна.

### 2.2. Исходный код PostgreSQL

Шаблон (единственно допустимый):

```
https://github.com/postgres/postgres/blob/083ac033419f690758508e08c1736089384bbee8/<путь-к-файлу>
```

Примеры:

```text
https://github.com/postgres/postgres/blob/083ac033419f690758508e08c1736089384bbee8/src/backend/access/heap/heapam.c
https://github.com/postgres/postgres/blob/083ac033419f690758508e08c1736089384bbee8/src/backend/storage/buffer/README
```

Правила:

- В ссылке всегда полный 40-символьный SHA; короткий SHA, имя ветки (`master`,
  `REL_17_STABLE`), тег `REL_17_11` в URL не используются — только хеш.
- Якорь на строки (`#L123` или `#L123-L140`) добавляется **только если** номера строк
  лично проверены на базовом коммите. Если строки не проверены — ссылка даётся на файл,
  а нужная функция называется в тексте главы.
- Якоря вида `#функция` на GitHub в blob-ссылках не существуют; якорь = только `#L<строки>`.

## 3. Общие правила проекта

1. **Целевая аудитория.** Разработчик, знающий основы программирования, но не базы данных.
   Уровень — от нуля до junior/junior+. Темы уровня middle+ и эксплуатации (репликация,
   кластеризация, шардирование, тонкая настройка GUC, бэкапы, мониторинг) в основной
   материал **не входят**.

2. **Фокус — разработка.** SQL, проектирование схем, транзакции, MVCC, индексы и планы,
   внутреннее устройство на концептуальном уровне, функции/процедуры, безопасность на
   уровне разработчика.

3. **Никакого выполнения SQL.** Учебник — статические HTML-файлы. Примеры SQL и C-кода
   оформляются как подсвеченные блоки **без** кнопок «Выполнить». Интерактивность
   ограничена: навигация, сворачиваемые блоки, вопросы «Проверь себя» с эталонными
   ответами, скрытыми по клику.

4. **Достоверность.** Каждое утверждение о поведении PostgreSQL подкрепляется ссылкой на
   официальную документацию (только `/docs/17/`) или исходный код (только базовый коммит,
   раздел 1). Запрещено выдумывать имена каталогов, полей, функций, параметров GUC, путей
   в исходниках. Если путь или имя не удаётся проверить — ставится пометка
   «ТРЕБУЕТ УТОЧНЕНИЯ» (см. раздел 4).

5. **Единый базовый коммит.** Все ссылки на исходный код PostgreSQL привязаны к коммиту
   `083ac033419f690758508e08c1736089384bbee8` (тег `REL_17_11`, релиз 17.11). Этот SHA
   используется во всех файлах учебника без исключений. Формат ссылки — раздел 2.2.

6. **Версия документации.** Все ссылки на postgresql.org используют префикс
   `https://www.postgresql.org/docs/17/`. Ссылки на «current» и на другие версии
   запрещены.

7. **Теория БД и SQL** подаётся ровно там, где без неё непонятно поведение PostgreSQL:
   не отдельным курсом, а встроенными вставками.

8. **Язык.** Текст — русский. Примеры кода и SQL — на английском, как в документации.

## 4. Правило «ТРЕБУЕТ УТОЧНЕНИЯ»

При **любом** сомнении в пути к файлу, имени каталога, поля, функции, параметра GUC или
номере строки — в текст главы вставляется пометка:

```text
ТРЕБУЕТ УТОЧНЕНИЯ: <что именно нужно проверить>
```

Формат обязательного содержимого пометки:

- **что проверить** — файл, функцию, структуру, параметр;
- **где проверять** — репозиторий postgres/postgres на базовом коммите
  `083ac033419f690758508e08c1736089384bbee8` либо документация `/docs/17/`;
- **почему возникло сомнение** — например, «имя взято по памяти, источника нет».

Пример:

```text
ТРЕБУЕТ УТОЧНЕНИЯ: имя структуры заголовка строки страницы. Проверить определение
struct в src/include/storage/bufpage.h на базовом коммите; имя PageHeaderData
взято по памяти, документация это имя не описывает.
```

Пометка «ТРЕБУЕТ УТОЧНЕНИЯ» не удаляется и не заменяется предположением. Она снимается
только фактической проверкой по базовому коммиту или документации — с заменой текста
на достоверное утверждение со ссылкой (разделы 2.1–2.2).
