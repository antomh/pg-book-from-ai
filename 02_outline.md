# 02_outline.md — Оглавление и каркас интерактивного учебника по PostgreSQL

Основания: правила — `00_rules.md` (PostgreSQL 17.11, базовый коммит
`083ac033419f690758508e08c1736089384bbee8`, документация `/docs/17/`);
состав тем — `01_analysis_and_topic_map.md` (DAG `T01–T51`).

Каркас создан: 11 модулей, 51 глава, 51 HTML-заглушка, навигация, подсветка,
каркас «Проверь себя». Заглушки содержат только заголовок, метаданные главы и
TODO-комментарий с пререквизитами.

## 1. Формат и технологические решения

- Статические HTML-файлы; открытие двойным кликом из файловой системы, без
  сервера и без сети (все ресурсы локальные).
- Никакого выполнения SQL в браузере, никакого PGlite, никакого локального
  сервера. Интерактивность: навигация, сворачиваемые блоки, «Проверь себя».
- Подсветка синтаксиса SQL и C — highlight.js 11.12.0, локальные копии
  `js/vendor/highlight.min.js` (common-бандл, включает SQL и C) и темы
  `css/vendor/hl-github.min.css`. Лицензия — `js/vendor/highlight.LICENSE`.
- Сворачиваемые блоки — нативные `<details>/<summary>`; стили в `css/book.css`.
- «Проверь себя» — два механизма (только клиентская логика, без SQL-движка):
  1) `<details class="quiz">` с эталонным ответом, скрытым до клика;
  2) каркас радиовопросов `.quiz` + кнопка «Проверить» в `js/book.js`
     (сравнение выбора с `data-correct`, раскрытие разбора при верном ответе).
- Навигация: боковое меню рендерится из `js/nav.js` (единый источник — данные
  этого оглавления); хлебные крошки — статический HTML в каждой странице и
  работают без JavaScript; при отключённом JS сайдбар заменяется ссылкой на
  оглавление (`<noscript>`).
- Разметка примеров: SQL — `<pre><code class="language-sql">`, C —
  `language-c`, примеры вывода psql/EXPLAIN — `<pre class="sample-output">`
  (без подсветки, серым — это «скопированный вывод», а не код).

**2.1.** Список выборки, выражения, `WHERE`; `NULL` — маркер отсутствия
значения; трёхзначная логика (`TRUE/FALSE/NULL`). **Теория (усиление):**
семантика NULL по стандарту SQL. Результат: предсказывает результат
`WHERE col = NULL`, пишет корректные проверки `IS NULL` / `IS NOT NULL`.
Источники: S1 `tutorial-sql.html`, `queries.html`, `functions-comparison.html`
(S1, раздел NULL-предикатов); S5 (гл. 3).

**2.2.** `ORDER BY` (в т.ч. по выражению и `NULLS FIRST/LAST`), `LIMIT/OFFSET`,
`DISTINCT`. Результат: управляет порядком и объёмом выдачи; формулирует,
почему `LIMIT` без `ORDER BY` даёт недетерминированный набор строк.
**Пометка:** `LIMIT/OFFSET`, `DISTINCT ON` — расширения PostgreSQL; стандарт —
`FETCH FIRST n ROWS ONLY` (S1: `queries-limit.html`). Результат также: знает,
что `NULLS FIRST/LAST` — расширение.

**2.3.** `INNER/LEFT/RIGHT/FULL/CROSS JOIN`, `ON` vs `USING`, `NATURAL JOIN`
(с предостережением). **Теория (усиление):** формальное определение соединения
в реляционной алгебре: декартово произведение + селекция (θ-соединение);
`LEFT JOIN` как θ-соединение с NULL-дополнением. Результат: по паре таблиц и
типу JOIN предсказывает состав и количество строк результата (включая
дублирование при 1:N). Источники: S1 `tutorial-join.html`, `queries.html`
(раздел Table Expressions), S5 (гл. 4).

**2.4.** Агрегатные функции (`count/sum/avg/min/max`), `GROUP BY`, `HAVING`,
`FILTER (WHERE ...)` (расширение PostgreSQL). **Теория (усиление):** агрегат
как свёртка множества; почему столбец вне `GROUP BY` не может попасть в список
выборки без агрегата. Результат: пишет корректные запросы с группировкой;
объясняет пользователю ошибку `column must appear in the GROUP BY clause`.
Источники: S1 `queries.html` (раздел агрегатов), S2 (гл. 6.3), S5 (гл. 3.7).

**2.5.** Скалярные подзапросы, `IN`/`NOT IN` (и их NULL-ловушку), `EXISTS`,
коррелированные подзапросы, `ANY/ALL`. Результат: выбирает между `IN` и
`EXISTS`, понимает семантику коррелированного подзапроса. Источники: S1
`queries.html` (подраздел Subqueries), S2 (гл. 6.4), S5 (гл. 3.8).

**2.6.** `WITH` как способ разбить запрос на шаги; `MATERIALIZED` /
`NOT MATERIALIZED` (расширение PostgreSQL). Результат: переписывает вложенные
подзапросы в цепочку CTE и наоборот. Источники: S1 `queries-with.html`, S5.

**2.7.** `WITH RECURSIVE`: якорная и рекурсивная части, остановка по пустому
результату. Результат: обходит дерево (materialized path / adjacency list) и
агрегирует по уровням. Источники: S1 `queries-with.html`, S5 (гл. 5.4).
**Пометка:** тема помечена J+.

**2.8.** `OVER (PARTITION BY ... ORDER BY ...)`, ранжирующие и смещённые
функции (`row_number`, `rank`, `lag/lead`), кадры (`ROWS BETWEEN ...`).
**Теория (усиление):** отличие оконной функции от агрегата — свёртка строк
против вычисления по кадру. Результат: нумерует строки внутри групп, считает
нарастающий итог. Источники: S1 `tutorial-window.html`, `functions-window.html`.

## 5. Ограничения формата

Что невозможно показать интерактивно в статическом учебнике без выполнения
SQL, и чем это компенсируется:

1. **Планы с реальными метриками.** `EXPLAIN (ANALYZE, BUFFERS)` зависит от
   данных, статистики и оборудования; в браузере его не получить. Компенсация:
   статические примеры планов, каждый с указанием происхождения; учебные
   планы, полученные автором на эталонном наборе данных, сопровождаются
   детальным разбором по строкам. Числа в планах — иллюстрация метода чтения,
   а не эталон.
2. **Конкурентное поведение.** Изоляция, блокировки, дедлоки требуют двух
   параллельных сессий. Компенсация: сценарии «сессия A / сессия B» в виде
   таблиц-диаграмм с пошаговой шкалой времени и предсказуемым исходом каждого
   шага; эталонные ответы в «Проверь себя» формулируются как «какой результат
   увидит сессия A».
3. **Ошибки и вывод psql.** Реальный вывод консоли воспроизводится только
   текстом: блоки `<pre class="sample-output">`, визуально отделённые от кода;
   каждая команда и её «вывод» связаны явно (команда → ожидаемый вывод).
4. **Статистика и оценки планировщика.** Зависят от данных; компенсация:
   фиксированные учебные наборы данных (описанные таблицы с точным числом
   строк), для которых в тексте посчитаны оценки вручную.
5. **Влияние объёма данных.** Разницу «100 строк против 10 млн» нельзя
   ощутить; компенсация: количественные рассуждения и графики (SVG в
   `assets/`) с явно указанными допущениями.
6. **Производительность.** Никаких измерений в браузере; все утверждения о
   скорости — качественные (O-нотация, сравнение методов) со ссылками на
   документацию, без выдуманных цифр.
7. **Версионная зависимость.** Все примеры описывают поведение PostgreSQL
   17.11; там, где поведение отличается между версиями (например, документы
   по изоляции), это указано в тексте главы со ссылкой на документацию.
